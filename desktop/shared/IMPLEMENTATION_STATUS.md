# XAN Desktop parity audit

The source of truth for this audit is the Android application in `mobile/android/app/` plus the five user-supplied implementation and screenshot specifications. This file records verified desktop behavior, not intended behavior. Update a row only after exercising the UI or a meaningful test for it.

## Current build snapshot

Version check on 2026-10-11: Android declares **1.0.0**, and desktop/iOS versions derive from `mobile/android/version.properties`; explicit release overrides must match it. The shared desktop project is `desktop/shared/`, and the iOS project is `mobile/ios/`. The release workflow builds Windows, macOS, and Linux packages with checksums. Windows signing is conditional on its configured certificate; macOS signing/notarization is conditional on Apple credentials. Cross-platform install, playback, credential-store and native-session QA remains. The runtime includes `java.sql` and `java.net.http`.

## Work sequence

1. Foundation: versioned catalogue database, persistent settings/data, provider boundaries, logs.
2. Playback: in-app InnerTube/yt-dlp resolution, queue and player, then playback-timed scrobbling and integrations.
3. Library: local scanner, playlists, downloads index, import/export and storage controls.
4. Experience: Android-aligned Home/Search/Library/recognition, themes, lyrics and settings parity.
5. System: privacy, updater, About/community, cross-platform native integration and packaging QA.

Rows remain partial or missing until runtime evidence proves the feature works.
