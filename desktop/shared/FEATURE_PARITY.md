# XAN Desktop feature parity checklist

Android remains the reference implementation. This checklist reflects source inspection and the desktop tests recorded in [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md). A checked item means the desktop flow has implementation evidence; it does not imply cross-platform runtime validation.

Version check on 2026-10-10: Android declares **1.0.0** (version code `7000030`). Desktop and iOS derive app versions, the Listen Together protocol, and logo resources from Android during their builds. Desktop CI, iOS CI, and the Android Platform Parity report now run when any file under `mobile/android/` changes. Android 1.0.0 added an optional video-source flow; its desktop and iOS parity gaps are listed below. The shared desktop project is `desktop/shared/`, and the iOS project is `mobile/ios/`.

Legend: `[x]` implemented and covered by a meaningful test or smoke check, `[~]` partially implemented or awaiting device/platform QA, `[ ]` absent.

## Application shell and navigation

- [x] Compose-based desktop window, all nine current Android AppLogo marks synced by `syncAndroidLogoLibrary`, theme palettes, persistent logo selector, and Magnet/mini navigation choice. Gold is the first-run default to match the supplied XAN logo; changing the logo updates the app window and system tray.
- [~] Optional persistent desktop sidebar for Home, Search, Library, Recognize Music, and Settings. It can collapse to icons, collapses automatically in narrower windows, and persists its layout choice in app preferences and backups. Sidebar resizing and destination changes animate unless Reduced motion is enabled; cross-platform visual QA remains.
- [x] Resizable window, custom title bar, minimize/maximize/close, and Magnet docking/animation.
- [~] Android screen and navigation parity across Home, Search, Library, Artist, Albums, Playlists, Settings, About, lyrics, and recognition; several Android screens and controls remain absent.
- [~] Focused-window shortcuts and tray controls are available. Settings → Media Controls can enable system-wide play/pause/previous/next/stop keys through JNativeHook, and offers OS sound settings plus configurable DJ fade transitions. Runtime permission and key mapping still need target-platform QA; native media sessions and direct output-device routing remain absent.

## Music discovery and library

- [x] YouTube Music search and metadata through the existing InnerTube sources; YouTube search fallback is opt-in and off by default.
- [~] Desktop Home mood chips now send each InnerTube endpoint's own `browseId` and `params`, reject stale responses, and restore the prior feed on errors. iOS Home parses real YouTube Music song/artist/album/playlist shelves, opens playback or the matching detail page, and has loading/error handling. The desktop endpoint mapping and iOS fixture parsing pass tests; personalized Android Home sections, account/local shelves, live feeds, and screen-level visual parity still need more QA.
- [x] Artist, album, and playlist detail lookup; download and saved-to-library actions; saved artists/albums/online playlists have Library views.
- [~] Android 1.0.0 video flow is now partly available: **Search → Videos only** searches YouTube and enabled NewPipe services, plays progressive H.264 MP4/M4V directly, and prepares adaptive HLS/DASH or split audio/video formats with yt-dlp plus system-installed FFmpeg before playback/download. Adaptive formats require FFmpeg on PATH; source and target-platform QA remains. iOS has no equivalent video flow yet.
- [~] Local music folder picker, tag scan, watcher, indexed library, downloads, favorites, listening history, and local playlists. Desktop playlists accept tracks from search/library/player, support per-song removal and ordering, and persist editable names/descriptions in SQLite. Linked YouTube Music playlists now reconcile track additions, removals, duplicate counts, and order. If any local track lacks a YouTube Music ID, that cloud playlist stays in safe partial-sync mode until the track can be matched. Account playlists can be imported or refreshed into a local copy from their detail page; live account verification remains.
- [~] Spotify public playlist import and matching; real playlist matching, ambiguity handling, and editing imported Spotify metadata remain.
- [~] YouTube Music session cookie support through OS credential storage, active channel discovery, persisted channel identity, channel switching, Android-aligned personalized browse toggle (on by default), and account library sync for liked songs/albums/playlists and followed artists. Library snapshots are stored per selected channel in SQLite and replaced atomically; sync is explicit from Library → YouTube Music. Account settings offer disconnect with or without clearing synced snapshots. Embedded Google sign-in cannot use an in-app webview; desktop still needs a registered OAuth Desktop client and browser-based PKCE flow. Authenticated account/library sync needs live verification.

## Playback and integrations

- [~] Embedded JavaFX playback, queue, seek, volume, repeat, shuffle, streaming recovery, and bounded yt-dlp fallback. Clicking the now-playing artwork/title or lyrics button opens an expanded player with cover art, transport/volume/seek controls, and synchronized lyrics beside it. The now-playing bar animates into the larger canvas inside the app window; end-of-track queue continuation has media-integration coverage on Linux/macOS CI, while interactive Windows/macOS device verification remains pending.
- [~] Desktop Now Playing includes Android's 5–120 minute sleep timer in 5-minute steps and a pause-at-track-end option. Countdown, change, cancellation, stale callback protection, Cast timed pause, and Listen Together pause publication are implemented; end-of-track mode is unavailable while casting. Shared timer state tests pass; manual device and Cast testing remain.
- [~] Native system-tray transport controls (play/pause/previous/next), window restore, and close-to-tray background playback while audio is active. These controls reuse the in-app playback queue, include Cast playback, and expose a Quit action. Optional global media-key hooks are implemented; native media sessions, per-device audio routing, and Windows/macOS/Linux runtime verification remain.
- [~] Last.fm, ListenBrainz, Discord Rich Presence, SponsorBlock, Cast, and equalizer are connected; live service/device testing remains.
- [~] Lyrics providers, timed/word-synced display, and recognition flow are implemented. Offline romanization can be toggled in the lyrics panel or Settings and currently covers Japanese (Kuromoji), Korean, Cyrillic, Hindi, and Punjabi. Explicit AI translation and AI romanization use the user's OpenRouter key stored in the OS credential store; lyrics are sent only after pressing Translate or AI romanize, and results are cached in SQLite by track, lyric content, mode, and target language. Chinese romanization is available through AI only; microphones and platform permissions remain parity gaps. Offline romanization is approximate for languages that need word-level pronunciation context.
- [~] Listen Together desktop room creation/joining, shared Android JSON protocol, room state and membership, host permissions, playback and queue sync, secure session token persistence, ping, and reconnect. Reconnect retries indefinitely with exponential backoff capped at 32 seconds and resets after the server confirms the saved session. Desktop offers Android's Cloudflare provider and optional Hugging Face endpoint; Cloudflare is the default, legacy Render URLs migrate to Cloudflare, and custom endpoints are preserved. A live Android↔desktop session is not runtime verified yet, so room flow, reconnection under network loss, and cross-platform playback still need QA.
- [~] Expanded player supports a saved animated album-art canvas and audio-reactive ambient spectrum visuals behind playback controls and lyrics, with Reduced motion/Reduced transparency support. The expanded player can load paginated public YouTube comments. Settings → Media Controls provides adjustable track fade-in/fade-out DJ transitions; beat matching and multi-deck mixing remain absent.
- [~] Japanese dictionary romanization is a removable optional feature pack stored outside the app bundle. Settings → Lyrics downloads and removes it; a release workflow publishes a self-contained, SHA-256-checked pack. Availability depends on a published release asset.

## Settings, data, and updates

- [~] Desktop settings include a searchable hierarchy and shortcut help, with SQLite catalogue, persistent preferences, credentials, diagnostics, backup/restore, privacy controls, storage limits, and a verified GitHub updater.
- [~] Desktop and iOS app versions derive from Android's `XAN_VERSION`; native Windows/macOS installer versions map 0.x to 1.x for package upgrade ordering and `jpackage` compatibility. The Android-triggered CI matrix now builds the 1.0.0 packages on all supported desktop runners; signed release installers remain unverified. Historical local MSI testing used XAN 0.9.9 and the installed local app reported 1.9.6. Windows policy verification did not trust the self-signed certificate.
- [ ] Linux AppImage build and runtime verification; DEB/RPM targets are configured but have not been tested on Linux.
- [~] macOS Intel and Apple Silicon packaging targets need separate CI builds and runtime verification. macOS keychain, permissions, signing, and notarization need Apple credentials.
- [ ] Windows ARM64 native package: the current JavaFX 21 dependency does not publish Windows ARM64 media binaries. Do not label the x64 package as a native ARM64 build.
- [~] Release workflow builds Windows x64, macOS Intel/Apple Silicon, and Linux DEB/RPM/AppImage packages with per-asset checksums; Windows signing uses optional repository certificate secrets, and macOS signing/notarization is wired for optional Apple credentials. Live release publication and signed installer verification still require configured credentials and an actual release run.

The 0.9.9 MSI is packaged but has not been installed. Clean-machine installation, expanded-player interaction, window scaling, media controls, and audio output selection remain unverified.
- [ ] Linux AppImage/DEB/RPM launch, desktop integration, audio backend, and persistence.
- [ ] macOS Intel/Apple Silicon launch, Keychain, permissions, signing, notarization, media controls, and audio.
- [ ] Cross-platform Listen Together synchronization, queue/host permissions, reconnect after network loss, and Android interoperation (implementation is present; live multi-client QA remains).
- [~] Authenticated account/session behavior and a local snapshot of the selected channel's liked songs, albums, followed artists, and playlists. YouTube Music playlists can be pushed from local copies and imported or refreshed from the selected channel; playlist track removals, duplicate counts, and ordering now reconcile when every local track has a YouTube Music ID. Account-managed favorites, avatar upload parity if available in Android, system-browser OAuth setup, and live cross-device verification remain.


## iOS and iPadOS status

- [~] Shared Compose shell, Android Listen Together protocol, secure room transport, host permissions, room roster, playback-state synchronization, and Keychain room-session storage are implemented in `mobile/ios/`.
- [~] iOS Magnet stays global across pages, uses a backgroundless hub with spring-animated navigation attachments, can be dragged and docked to the nearest window edge, and persists its position. Settings can switch to a compact bottom navigation bar and disable Magnet motion. Pure layout tests cover all four docking edges; touch and visual behavior still need iPhone/iPad QA.
- [~] iOS logo picker mirrors Android's current nine PNG marks, defaults to the requested gold mark, and persists selection; build-time resource sync and the app icon generator use the Android gold source asset.
- [~] Native AVPlayer playback, audio-session category, room track metadata in Control Center/lock screen, headset commands, and synchronized room play/pause/skip/seek are implemented. Room state updates apply directly to AVPlayer; lock-screen, headset, and dock commands use shared room permissions and server synchronization. Background audio capability, lifecycle room reconnect, safe areas, iPhone/iPad orientation configuration, icon, launch screen, and persistent room server/name preferences are present. Xcode and device verification remain unavailable on this Windows host.
- [~] iOS now exposes Android-style shuffle and repeat-off/all/one controls in the native playback dock and Queue screen. The mode state drives the shared queue and multi-file native import order, persists when “Remember shuffle and repeat” is enabled (default on), and is disabled while Listen Together owns playback. Queue, mode restoration, and repeat behavior tests pass; the Swift bridge and device controls still need the macOS build and Apple-device QA.
- [~] iOS Queue now includes Android's sleep timer: 5–120 minute countdown in 5-minute steps, pause at the end of the current track, and change/cancel controls. Timed pause is scheduled in the Swift audio host for background playback, with a shared Kotlin deadline countdown, stale-callback protection, and Listen Together pause routing. State tests pass; background firing still needs Apple-device QA.
- [~] iOS search/detail pages, local playlists/favorites, Spotify public playlist preview matching (up to 50 visible tracks), provider-cookie Keychain storage, settings, native local/stream playback, persistent Files imports, and offline audio downloads are implemented. Search covers songs, videos, artists, albums, community playlists, and featured playlists with Android's InnerTube category filters; Home, search, account-library, and local library music rows render allowlisted catalog artwork with a failure fallback. Track downloads are available in search and catalog rows; artist, album, and playlist detail pages can queue their listed tracks. Native URLSession downloads AAC M4A into app support, indexes files locally, and AVPlayer can play them offline. Files imports are copied into app support, indexed in the shared Library with available file metadata, and can be played or removed. The selected channel's saved playlists, albums, and followed artists are cached locally and remain visible if refresh fails. Spotify account login, XAN profile synchronization, avatar uploads, full Android navigation, and screen parity remain unfinished. iOS native import/download/playback and visual flows still need Simulator/device verification. See `mobile/ios/FEATURE_STATUS.md`.
- [~] iOS Last.fm accepts user-owned API credentials, authorizes through Safari, stores secrets and session tokens in Keychain, and sends now-playing/scrobble requests using the Android default threshold (half the track, capped at 50 seconds, with a 30-second minimum duration). Live authorization, submissions, and playback behavior remain unverified on an Apple device.
- [~] iOS ListenBrainz validates user tokens, stores them in Keychain, and sends now-playing and qualifying listen submissions after `min(half the track, 4 minutes)` of accumulated playback. API/device behavior remains unverified on an Apple device.
- [~] iOS lyrics now support all 11 Android providers, including YouTube transcript captions and YouTube Music track-linked lyrics. Provider switches and priority persist in Settings; providers run concurrently and rank word/syllable timing above line timing and plain text, with saved order breaking ties; requests include album/duration/track ID when known; YouLyPlus queries six mirrors concurrently and ranks word/syllable timing; Paxsenix uses Apple Music song search and TTML/syllable payloads; KuGou duration-matches and decodes timed LRC; Musixmatch signs its web requests through native CryptoKit HMAC. Bini downloads are allowlisted and redirect-checked; bounded TTML parsing rejects DTD/entity declarations; Unison results include attribution. Rich LRC, TTML, YouLyPlus, and Paxsenix word timing renders karaoke highlights. Shared tests cover provider parsing, saved-order normalization and ranking, YouTube Music lyrics endpoint parsing, request signing/date formatting, rich LRC timing, TTML parsing, and Bini URL validation; YouLyPlus/Paxsenix/KuGou and YouTube Music live checks passed. Musixmatch's current token endpoint returns app status 401 with hint `upgrade` on the build host. iOS offline Any-Latin script romanization needs no API key; language-specific tuning remains. AI translation/romanization setup requires a user API key, and translated lines persist in a bounded local cache; Apple-device verification remains.
- [ ] macOS Xcode/Simulator build, Swift bridge, Keychain, physical device, room-server, background/interruption, and TestFlight checks are unverified from this Windows machine.
- [~] `.github/workflows/ios-ci.yml` builds/tests the unsigned iOS Simulator app on macOS. `.github/workflows/ios-release.yml` can export and attach an IPA when Apple signing variables/secrets are configured; TestFlight/App Store submission and notarized signing still require Apple Developer credentials and App Store Connect access.
