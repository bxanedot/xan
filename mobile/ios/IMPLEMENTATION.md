# XAN iOS and iPadOS

See [FEATURE_STATUS.md](FEATURE_STATUS.md) for the requirement-by-requirement parity audit and verification limits.

The iOS target lives in `mobile/ios/` and uses Kotlin Multiplatform plus Compose Multiplatform. It targets iPhone and iPad from one universal iOS application. Its room transport compiles the existing Android `Protocol.kt` directly into `commonMain`; it talks to the same centralized WebSocket room endpoint used by Android and XAN Desktop. This is an incremental shared layer because the current Android application UI, media pipeline, account repository, and settings are tied to Android APIs and are not yet platform-neutral.

## Build on macOS

Install Xcode, Xcode command-line tools, JDK 21, and XcodeGen. From the repository root:

```sh
chmod +x mobile/android/gradlew
brew install xcodegen
cd mobile/ios/iosApp
python3 ../generate-project-spec.py
xcodegen generate --spec project.generated.yml
cd ../../..
./mobile/android/gradlew -p mobile/ios :iosShared:compileKotlinIosSimulatorArm64 :iosShared:compileTestKotlinIosSimulatorArm64
cd mobile/ios/iosApp
xcodebuild -project XAN.xcodeproj -scheme XAN -configuration Debug -destination 'generic/platform=iOS Simulator' -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build
```

GitHub Actions runs the simulator framework tests and unsigned simulator app build on `macos-15`. iOS Gradle compilation runs `syncAndroidLogoLibrary` first, copying current Android AppLogo marks into Compose resources; the app-icon generator reads Android's Gold source directly. Any Android source change triggers this iOS build. Windows can compile the Kotlin common metadata and shared Android room protocol, but it cannot build or launch an Apple framework or simulator.

## Signing and TestFlight

The `iOS Signed Release` workflow attaches a signed IPA to a published release when these repository settings are present:

- Variable `APPLE_TEAM_ID`
- Variable `APPLE_PROFILE_NAME` (the profile installed for `app.xan.ios`)
- Secret `APPLE_CERTIFICATE_P12_BASE64`
- Secret `APPLE_CERTIFICATE_PASSWORD`
- Secret `APPLE_PROVISIONING_PROFILE_BASE64`

Create an App Store distribution certificate and App Store provisioning profile for bundle ID `app.xan.ios`. The workflow stores signing material in a temporary runner keychain and does not commit it. App Store Connect API credentials and an Apple Developer Program membership are still needed for full App Store submission; the generated IPA can otherwise be uploaded manually to TestFlight.

## Current scope and gaps

Implemented in this iOS foundation: a Compose Multiplatform Home, Search, Library, Queue, Listen Together, Settings, and About shell; secure WSS room create/join; host/control state; roster and playback-state reception; Keychain room-token persistence; reconnect and lifecycle handling; safe-area padding; a width-constrained iPad layout; and iPhone/iPad/orientation configuration. The UI has a persisted gold-ring/Android-logo selector, Android-aligned palettes and font choices, and the movable animated Magnet. Search and Home use the shared Ktor InnerTube client for YouTube Music songs, artists, albums, playlists, and shelves; artist/album/playlist detail pages display their descriptions and track lists. Search results can be liked, added to local playlists or the playback queue, or sent to the Swift AVPlayer host for playback inside XAN. Local playlists persist on-device and support rename, delete, track removal, and queue playback. The Library imports Spotify's public embed preview, matches up to 50 visible tracks against YouTube Music with bounded concurrency, saves successful matches as a persistent local playlist, and reports unmatched tracks and possible truncation; Spotify sign-in and private playlists are not supported. Last.fm settings accept a user-owned API key and shared secret, authorize in Safari, store secrets in Keychain, and submit now-playing and thresholded scrobbles during playback. ListenBrainz settings validate and store a user token in Keychain, submit now-playing updates, and scrobble after the official half-track/four-minute threshold; live service verification remains. Lyrics support Android's 11 providers, including YouTube transcript captions and the YouTube Music track-linked lyrics browse endpoint. Enable switches and provider priority persist in Settings; active providers are queried concurrently, ranking word/syllable timing above line timing and plain text, with the saved order breaking ties; album, duration, and track ID are sent when known; YouLyPlus queries six mirrors concurrently and ranks word/syllable timing above synced or plain fallback; Paxsenix searches Apple Music and parses TTML/syllable payloads; KuGou filters by duration and decodes synced LRC; Musixmatch uses native CryptoKit HMAC signing. Bini download URLs and redirects are restricted to HTTPS allowlisted hosts; TTML input is bounded and rejects DTD/entity declarations; Unison results display attribution. Timed lines follow AVPlayer progress, and rich LRC, TTML, YouLyPlus, and Paxsenix timings highlight the current word. Opt-in live checks for YouLyPlus, Paxsenix, KuGou, and YouTube Music lyrics passed. Musixmatch currently receives app status 401 with hint `upgrade` from its token endpoint and falls through. Offline script romanization uses Core Foundation Any-Latin transliteration with persisted show/use-as-main controls and no API key; it does not yet match Android's per-language transliteration tuning. OpenAI-compatible translation, AI romanization, and transcription run on user request; settings and a bounded local translation cache persist across restarts, and the API key is stored in Keychain. No live model check ran without a user key. Apple-device verification remains. Album, artist, and playlist pages can play all tracks, download them for offline use, or enqueue the remaining tracks in a Listen Together room. Native next/previous controls advance through the shared local playback queue; a global Queue page displays and edits local or room queues. Direct InnerTube AAC resolution falls back to native YouTubeKit 0.4.9 local extraction, pinned to a specific source revision. The highest-bitrate native M4A audio stream is passed to AVPlayer. Extraction is bounded/cancellable; both resolver outputs must use HTTPS Google Video URLs. The native Swift path needs macOS/device verification, including ciphered and restricted tracks. Settings can save or remove an imported YouTube Music SAPISID cookie in Keychain; search and playback attach it only to YouTube Music requests. Full Android screen/settings parity, XAN profile editing and avatar upload, cloud-synced playlists and preferences, Discord playback integration, additional lyrics providers and live translation service QA remain. Common tests cover room protocol, cookie validation/storage, song/artist/album/playlist search and detail parsing, Spotify playlist parsing and match scoring, Last.fm API signing/scrobble thresholds, ListenBrainz token/threshold/payload behavior, BetterLyrics/BiniLyrics/Unison/Musixmatch/YouLyPlus/Paxsenix/KuGou parsing, SimpMusic and YouTube Music lyrics parsing, provider-order normalization/movement/ranking, translation response alignment and HTTPS endpoint validation, rich LRC word timing, TTML safety, queue order/actions, AAC selection, unsafe/cipher-only stream rejection, library persistence and editing, and room-server URL rules. The opt-in live search and YouLyPlus/Paxsenix/KuGou mirror smokes passed previously; the YouTube Music next/browse lyrics smoke passed in this increment; Musixmatch token retrieval returned an app-level 401 `upgrade` response on the build host. The direct playback smoke was attempted and YouTube returned a bot-confirmation response on the build host, so the stream path is not yet live-verified.

The Swift host plays local audio files selected through Files, direct HTTPS audio URLs, and resolved YouTube Music AAC streams with AVPlayer. Picked audio is copied into XAN app storage, indexed with its available metadata in the shared Library, and can be played or removed after restarting the app. The global mini player, lock-screen and Control Center commands, headphone controls, playback progress, background audio mode, and interruption handling are connected. YouTube Music cover art is passed to the Swift player, checked against HTTPS and known image hosts, and loaded asynchronously for Now Playing. Room track changes resolve through the same in-app AAC playback path through direct AAC resolution or the native extraction fallback; room seek/play/pause updates apply to AVPlayer without echoing commands. iOS supports Android's 11 lyrics providers, including the same YouTube InnerTube transcript endpoint and the YouTube Music track-linked lyrics browse endpoint. Provider switches and priority persist in Settings; enabled providers run concurrently, ranking word/syllable timing above line timing and plain text, with saved order breaking ties; YouLyPlus races six mirrors, Paxsenix uses Apple Music search and timed syllable data, KuGou decodes timed LRC, and Musixmatch uses native CryptoKit HMAC signing. The build host live checks for YouLyPlus, Paxsenix, KuGou, and YouTube Music lyrics passed; Musixmatch token retrieval currently returns app status 401 with hint `upgrade` and falls through. TTML input is bounded and rejects DTD/entity declarations, Bini redirects are checked against the HTTPS host allowlist, and Unison lyrics display attribution. Rich LRC, TTML, YouLyPlus, and Paxsenix word timing highlight the current word as timed lines follow AVPlayer progress, with loading, retry, rate-limit, and unavailable states. Cross-platform room playback remains unverified on a live server and Apple device, and the Swift file-import bridge, extractor, remaining lyric network fallbacks, and AVPlayer-driven highlighting need Apple-device verification.

Full Android screen/settings parity, the XAN account/profile system, cloud-synced playlists and preferences, Discord playback integration, and remaining service integrations have not yet been moved into multiplatform modules. iOS already has local playlists, offline downloads, account-library snapshots, a YouTube Music cookie, Last.fm credentials, and a ListenBrainz token in Keychain. Last.fm authorization/scrobbling and ListenBrainz validation/submission are implemented but have not been tested against live accounts. The YouTube Music Settings sign-in sheet and native callback bridge can capture a cookie, but this WKWebView flow is experimental and unverified. Google blocks embedded sign-in and requires browser-based OAuth; an OAuth client is not configured here, so importing a cookie remains the known fallback. The room token and YouTube Music, Last.fm, and ListenBrainz credentials use Keychain. Full account and catalog parity remain unfinished. The Windows host can run shared JVM tests and compile the Android application but cannot link Apple frameworks, generate an Xcode project, run Simulator/device tests, exercise audio hardware, sign an IPA, or submit to TestFlight. Those checks need a macOS runner; signed release and App Store distribution also need Apple Developer credentials and App Store Connect access.

## Versions and extraction

On macOS, project generation also compiles the supplied gold XAN logo into an opaque 1024×1024 AppIcon using Core Graphics. The source artwork is preserved. Run the generator before XcodeGen for both Simulator and signed builds.

`generate-project-spec.py` reads `mobile/android/version.properties` (or `XAN_RELEASE_TAG`) and writes an ignored `iosApp/project.generated.yml`. The checked-in base specification is a template. [YouTubeKit notices](THIRD_PARTY_NOTICES.md) record the pinned source and license. No third-party remote extractor is enabled. Swift extraction, playback codecs, provider blocking, cookie-protected tracks, and background behavior need a real macOS/iOS test; shared JVM tests do not verify those native behaviors. Room snapshots use matched ping/pong server time, periodic state requests, and monotonic elapsed time during stream resolution. Settings select the same configured centralized room services as Android.
