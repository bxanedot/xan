# XAN iOS and iPadOS feature status

Android remains the source of truth. This is an implementation audit, not a promise of parity.

| Area | Status | Evidence and remaining work |
|---|---|---|
| Shared application framework | Partial | `mobile/ios/shared` uses Kotlin Multiplatform and Compose Multiplatform. Its shared UI now includes Home, Search, Library, Listen Together, and Settings; Android's remaining screens and repositories are still coupled to Android APIs. |
| iPhone/iPad layout | Partial | Safe drawing insets, a centered maximum-width content column, horizontal tab scrolling, both device families, and orientation declarations are configured. No Simulator or physical-device layout check has run. |
| Branding, themes, and motion | Partial | The iOS logo selector mirrors Android's current AppLogo catalog, defaults to the user's requested gold mark, and persists the choice; build-time resource sync and the generated app icon use Android's assets. It also matches Android's five app-font choices and persisted Chillax brand-font toggle, using the same bundled font assets. Five palettes persist, with a native audio dock. The backgroundless Magnet has spring-animated navigation attachments, drag-to-edge docking, saved position, a persisted mini-bar toggle, and a reduced-motion setting. Simulator/device visual and touch checks remain. |
| Accounts and profiles | Partial | Settings accepts the YouTube Music session cookie and stores it in iOS Keychain. XAN creates the time-bound SAPISIDHASH in memory, fetches the signed-in profile and channel list, persists the selected channel ID, and supports channel switching. Personalized browsing can be toggled and follows Android's default-on preference. A native WKWebView cookie-capture flow is wired but is experimental and not device-verified; Google blocks embedded sign-in and requires browser-based OAuth, so cookie import remains the known fallback until a supported OAuth client is configured. XAN profile editing and avatar uploads are not implemented. Live account endpoints need device verification. |
| Home, search, and catalog | Partial | Home fetches real YouTube Music shelves, retains chip endpoints, parses song/artist/album/playlist metadata, displays loading/errors, restores the prior chip on failure, and opens corresponding playback/detail flows. Search queries songs, music videos, artists, albums, community playlists, and featured playlists; category chips filter results and playlist results open their detail pages. Home, search, and account-library rows display allowlisted catalog artwork with a fallback mark. Artist pages show descriptions/tracks; album and playlist pages show details/tracks. When configured, browse, search, WEB_REMIX playback, and authenticated library requests include the saved account identity and SAPISIDHASH. AAC playback is passed to native AVPlayer, with pinned YouTubeKit 0.4.9 extraction as a fallback. Callback safety, account parsers, account-library shelf parsing, Home parsing, and playlist search parsing pass JVM tests; live endpoints, signature extraction, and Darwin playback remain unverified. |
| Video sources (Android 1.0.0) | Not implemented | Android added optional non-music video-source discovery, stream-format selection, in-app video playback, and video downloads. iOS currently searches music/video catalog results but does not expose Android's other-source setting, format picker, native video player, or offline video flow. |
| Library, playlists, downloads | Partial | Library loads the signed-in YouTube Music account's saved playlists, albums, and followed artists from the same InnerTube browse shelves as Android, caches a bounded snapshot for the selected channel, and shows that snapshot when refresh fails. It supports refresh/loading/error/empty states and opens each item in its in-app detail page. Detail back navigation returns to the originating Home or Library screen. Local playlist names and tracks persist in device preferences, can be renamed/deleted with a delete confirmation, and saved tracks can be played or removed. The Library imports Spotify public playlist previews: XAN validates the Spotify HTTPS link, reads at most a bounded embed response, matches up to 50 visible tracks against YouTube Music with capped concurrency, saves matched tracks as a restart-persistent playlist, and reports unmatched tracks and possible truncation. Spotify login and full private playlist access remain unavailable. Search and catalog rows can download tracks; artist, album, and playlist pages can queue or download all listed songs. The global Queue page supports direct selection, removal, clearing upcoming tracks, shuffle, repeat off/all/one, and persisted mode restoration matching Android's remember-shuffle-and-repeat setting; native next/previous and end-of-track events follow local modes. In a Listen Together room, the same page displays the server queue and supports add, remove, clear, and play actions under the room's host/control permissions; room playback modes remain server-owned. The native downloader validates HTTPS Googlevideo URLs before download and checks the final URL after redirects, rejects unsupported responses and files over 250 MiB, writes M4A files into app storage excluded from backup, and indexes them in the local library for AVPlayer offline playback/removal. Audio selected through the native Files picker is copied into XAN's imported-audio folder, indexed with available file metadata, and shown in the persistent Library with play/remove actions. Shared persistence, cache, path, filename, import metadata, Spotify parsing/matching, and queue-order tests pass. The Simulator/device import, download, storage, queue and offline playback flow has not been exercised. |
| Audio output | Partial | Native `AVPlayer` plays audio selected from Files, direct HTTPS audio streams, and YouTube Music search results through direct AAC resolution or the native YouTubeKit fallback. Picked files are copied into app storage so Library entries survive app restarts. Search-result playback sends title and artist metadata into the native mini player. Local multi-file next/previous, seeking, and visible stream errors are implemented. Room track changes now resolve through this in-app path and apply synchronized start position, seek, play, and pause state. Native extraction, restricted tracks, and broader XAN catalog playback still need target-device verification. |
| Sleep timer | Partial | The Queue screen offers Android's 5–120 minute timer in 5-minute steps, pause-at-track-end, countdown, change, and cancel actions. The shared timer state routes pause through Listen Together when active; the iOS host schedules a native background-capable dispatch timer and the shared countdown checks the deadline while the app is active. Generation checks prevent a stale native timer from cancelling a replacement. End-of-track pause takes precedence over repeat and queue advance. Shared tests cover timer countdown, end-of-track state, and stale callback rejection. Background firing and audio pause still need Simulator/device verification. |
| Lyrics | Partial | iOS now includes all 11 Android providers: BetterLyrics, BiniLyrics, Unison, Musixmatch, YouLyPlus, Paxsenix, LRCLIB, KuGou, SimpMusic, YouTube transcript captions, and YouTube Music track-linked lyrics. Provider enable switches and priority order persist in Settings. Providers run concurrently; word/syllable timing ranks above line timing and plain text, with saved order breaking ties. The default order matches Android. YouLyPlus races six mirrors; Paxsenix searches Apple Music and parses TTML/syllable payloads; KuGou duration-matches and decodes synced LRC; Musixmatch uses native CryptoKit HMAC signing. Bini URLs are HTTPS allowlisted and redirects checked; TTML parsing is bounded and rejects DTD/entity declarations; Unison results include attribution. Rich timing highlights the active word. Live checks for YouLyPlus, Paxsenix, KuGou, and YouTube Music passed on the build host. Musixmatch currently returns app status 401 with an upgrade hint and falls through. Offline script romanization uses Core Foundation Any-Latin transliteration with persisted show/use-as-main controls and no API key; it does not yet match Android's per-language transliteration tuning. OpenAI-compatible translation, AI romanization, and transcription run on user request; settings and a bounded local translation cache persist across restarts, with the API key stored in Keychain. No user API key was available for a live model check; Apple-device playback verification remains. |
| Last.fm scrobbling | Partial | Settings accepts a user-owned Last.fm API key and shared secret, signs API requests through the native host, opens Last.fm's authorization page in Safari, finishes the session exchange, and stores the credentials, temporary token, and session key in Keychain. Scrobble and now-playing preferences persist locally. Playback updates submit now-playing when enabled and scrobble after Android's default 30-second minimum-duration rule and `min(half the track, 50 seconds)` delay; album metadata is attached when available. Live authorization, service submissions, and device playback have not been verified. |
| ListenBrainz | Partial | Settings validates a user token against ListenBrainz, stores it in Keychain, and persists the scrobbling switch. Playback sends now-playing updates on track start/resume and submits a listen after accumulated playback reaches `min(half the track, 4 minutes)`. ListenBrainz's server can still reject a submission; API/device playback has not been verified. |
| Now Playing and remote commands | Partial | `AVAudioSession` and `MPRemoteCommandCenter` expose lock-screen, Control Center, and headset play/pause/skip/seek commands. When connected to Listen Together, those commands are sent to the shared room server and applied locally only when the room snapshot returns, avoiding client drift; owner-only permissions are honored. During disconnection or reconnect, commands stay local until the server accepts the session. Now Playing publishes title, artist, duration, current position, and rate. YouTube Music artwork is fetched asynchronously from allowlisted HTTPS hosts with an 8 MiB response cap and cached; local file artwork and iOS runtime verification remain. |
| Background and interruption handling | Partial | Audio background mode is declared and AVPlayer is configured for playback outside the foreground. Audio interruptions and headphone removal pause AVPlayer; room sockets close on background and resume from Keychain on foreground. A background room session cannot promise continuous synchronization. |
| Listen Together | Partial | The client reuses Android's serialized `Protocol.kt`, supports secure room creation/joining, roster/state/queue reception and editing, host control mode, Keychain session persistence, ping, reconnect, and room play/pause/skip/seek commands. Search selections during a room use the shared `CHANGE_TRACK` action; queue add/remove/clear actions use the same server protocol and room permissions. Incoming YouTube track IDs resolve to AVPlayer through direct AAC resolution or native extraction, and room position/play state updates are applied to the native player without echoing commands. Lock-screen, headset, and queue controls share the room's permission checks. Leaving, being kicked, or room closure stops room-managed audio; a reconnect is not treated as active until the server confirms it. Foreground reconnect retries indefinitely with exponential backoff capped at 32 seconds; backgrounding pauses retries and foregrounding restores the Keychain session. Local file IDs are not published to other clients. Cloudflare and optional Hugging Face providers come from Android's service properties; Cloudflare is the default, legacy Render origins migrate to Cloudflare, and custom endpoints are preserved. Matched ping/pong timing corrects clock offset; room state requests and monotonic elapsed time account for resolution delays. Live extraction, server behavior, and Android↔iOS playback still need device verification. |
| Credential storage | Partial | Listen Together reconnect tokens, the YouTube Music session cookie, Last.fm API key/shared secret/temporary authorization token/session key, and ListenBrainz user token use iOS Keychain. YouTube request signatures and Last.fm API signatures are generated in memory by the native host. XAN account login, XAN profile credentials, and cross-device preference synchronization are not implemented. Display name, server origin, service usernames, and scrobbling preferences use platform preferences. |
| App assets and configuration | Partial | App icon asset, launch background, Info.plist, iPhone/iPad families, and audio background capability are configured. Xcode asset compilation has not run on this Windows host. |
| Automated builds | Configured, partial verification | `ios-ci.yml` runs shared tests, iOS Simulator tests, and an unsigned Simulator build on `macos-15`. The hosted Simulator build and Swift bridge passed on `f4e5496` ([run 37987079746](https://github.com/bxanedot/xan/actions/runs/37987079746)). The Spotify importer, Last.fm Keychain/CryptoKit bridge, ListenBrainz Keychain bridge, and lyrics translation Keychain bridge in the latest changes still need hosted Xcode verification. The Windows host cannot independently compile the Swift host or run the iOS Simulator. |
| Signed IPA and TestFlight | Configured, unverified | `ios-release.yml` exports an IPA and checksum after validating Apple signing inputs and the profile's bundle ID/team. It has not run. Apple Developer membership, distribution certificate, provisioning profile, and App Store Connect upload access are required for signed distribution and TestFlight. |
